# Версии обращений и объяснение изменений

Цель: принять дополнения к тому же обращению, сохранить историю и объяснить,
почему текущие источники сигнала отличаются от подтвержденного снимка.
Требования из обсуждения: одинаковая версия не создает событие, старая не
затирает новую, новый симптом изменяет только связанные сигналы.

Выбранный инженерный подход: текущий staged_tickets сохраняется для существующего
анализа; отдельные таблицы содержат неизменяемые версии, указатель последней
версии и журнал изменений сигналов. Полное event sourcing потребовало бы заменить
хранилище и существующий workflow; перезапись без журнала теряет доказательства.
Python 3.11/3.12, SQLite, FastAPI; без новых зависимостей.

Контракт (инженерные решения): version — необязательное строго положительное
целое до 2^63-1. Начальная версия без поля = 1. Для изменения существующего текста
требуется явная версия больше текущей. Тот же номер с иным обезличенным содержимым
или старая версия дают 409 с откатом всего пакета. Продукт и канал не меняются;
occurred_at остается датой первоначального обращения, не временем обновления.
Более высокая версия с тем же текстом допустима, фиксируется один раз.
История обезличивается до записи. Конкуренция сериализуется BEGIN IMMEDIATE.

Пересчет: обновление несовместимого источника удаляет его из текущего состава
прежнего сигнала, сохраняя ID и историю карточки. Совместимый источник остается
с новой версией. Анализ может создать отдельный сигнал для нового симптома,
если есть минимум два подтверждающих обращения. Неоднозначные старые смешанные
карточки по-прежнему требуют аналитика. Ручные исключения не отменяются.
Пустой или одиночный текущий сигнал сохраняется, подтверждение при <2 запрещено.

Подтвержденные решения и product_queue.snapshot неизменяемы. Изменившиеся
доказательства отмечаются как требующие повторной проверки. Здесь не реализуется
новая процедура повторного подтверждения уже переданного сигнала или отправка
уточняющих вопросов пользователям.

Панель: версия каждого источника, последняя причина и разница активных источников,
история обновлений; API истории версий доступен с тем же токеном аналитика.

Уточнение по ревью: выводимый контекст старой карточки сохраняется до отделения
источников; совпадение с ее прежним ID не позволяет заменить смысл. Восстановление
пустой семантической карточки требует прежнего источника и не конкурирует с
карточкой, уже содержащей совпавшие источники.
