# Контрольный набор обращений ТИИм Pulse

Версия: `pulse-synthetic-v1`. Seed по умолчанию: `20261105`. Генератор использует только стандартную библиотеку Python и не вызывает модели или внешние сервисы. Данные полностью синтетические; названия продуктов вымышленные.

## Состав и разнообразие

Каталог содержит 30 семейств повторяемых сценариев с четырьмя независимыми формулировками каждого и шесть отдельных редких проблем. Формулировки описывают действие, наблюдаемый результат и контекст; встречаются синонимы, сокращения и разговорная речь. Дополнительные формы включают переписку, структурированную заявку, список шагов, длинный рассказ, шумную транскрипцию и текстовое представление вложения. При генерации вносятся опечатки, синтетические контакты и недоверенные инструкции.

Представлены ошибки, пожелания, вопросы, сервисные запросы, нерелевантные и неоднозначные обращения. Специально различаются исчезновение и дублирование автомобиля; отсутствие SMS и отклонение свежего кода; замена телефона и добавление второго контакта; ошибка 404 при записи и при скачивании отчета. Одни сценарии встречаются в трех продуктах, но не должны объединяться между ними.

Контрольный набор включает 500 независимых исходных обращений и 598 доставок событий: 500 исходных, 50 повторных доставок и 48 изменений. Изменения и повторы не являются новыми независимыми обращениями. Шесть редких проблем представлены по одному разу. Некоторые длинные сообщения содержат две задачи и требуют декомпозиции аналитиком.

Это композиционный синтетический набор, а не выборка реального потока. При увеличении размера повторно используются семейства и формулировки; рост числа строк не означает рост независимого семантического покрытия. Для оценки переносимости потребуется обезличенная корпоративная выборка.

## Файлы

| Файл для каждой выборки | Содержание | Кто использует |
| --- | --- | --- |
| `*.inputs.json` | Массив `id`, `product`, `text`, `channel` | Алгоритм / импорт MVP |
| `*.labels.jsonl` | Эталон на каждое исходное обращение | Только модуль оценки |
| `*.events.jsonl` | Источники, версии и повторные доставки пакетами | Будущие тесты ingestion |
| `*.event_labels.jsonl` | Ожидаемое действие на событие в порядке доставки | Только проверка обработки событий |
| `expert-review.csv` | 40 слепых примеров из development/validation | Независимые эксперты |
| `manifest.json` | Конфигурация, счетчики, версия, SHA-256 и размеры файлов | Проверка воспроизводимости |

Признаки не содержат категории, сценария, issue ID, intent, difficulty, security-меток или ожидаемого результата. ID обращения — непрозрачный хеш, без имени класса. Модели передается только разрешенный текст и исходные метаданные; никакие поля из файлов `labels` не добавляются в prompt, TF-IDF или embedding-вектор.

## Эталонная разметка

Каждая запись содержит `ticket_id`, `product_id`, `category`, `workflow`, `issue_id`, `gold_cluster_id`, `normalized_intent`, `source_channel`, `expected_signal`, `difficulty`, `security_test_type`, `ground_truth`.

`issue_id` обозначает эквивалентную описанную проблему или потребность, а не доказанную первопричину в исходном коде продукта. `gold_cluster_id` ограничен продуктом. Для вопросов, сервисных запросов, нерелевантного, неизвестного и многопроблемного текста единый кластер не задается. Редкая проблема имеет уникальный кластер из одного источника и не образует сигнал.

`expected_signal=true` означает наличие не менее двух независимых однопроблемных обращений этого продукта в данном эталонном кластере. Это ожидаемая допустимость кандидата, а не решение о публикации. Даже такой кандидат должен пройти проверку человеком. Категория многопроблемного текста соответствует основной задаче, все задачи перечислены в `ground_truth.issues`; для строгой кластеризации запись исключается до декомпозиции.

`ground_truth` также хранит семейство разделения, классы сложности случаев, необходимость декомпозиции, ожидаемую безопасную границу и статус экспертной проверки. Эталоны заданы каталогом, независимо от правил MVP. Автоматическая структурная валидация не доказывает семантическую верность этих эталонов.

Контакты используют домен `example.invalid` и невозможный код телефонного оператора `000`; они служат для тестирования маскирования. Инструкции атаки являются недоверенными данными. Их наличие не разрешает публикацию, вызов инструментов, раскрытие секретов или доступ к другим продуктам.

## Разделение и holdout

Пропорции: 60% development, 20% validation, остаток holdout. Сначала по категориям распределяются целые семейства сценариев, затем создаются обращения. Все формулировки, продукты, вторичные задачи многопроблемных сообщений и версии одного семейства остаются в одной выборке. Валидатор запрещает пересечения семейств, кластеров, ID и точных нормализованных текстов между выборками.

Development используется для разработки. Пороги настраиваются только на validation. Перед финальным прогоном сохраняются метод, версия, настройки, порог и хеши файлов; holdout используется один раз для итоговой оценки. Структурная проверка holdout допустима, подбор параметров по его меткам — нет. При изменении набора или использовании результатов holdout для разработки потребуется новая независимая версия проверки.

Изоляция семейств проверяет перенос на новые проблемы, поэтому доли классов по выборкам отличаются. Набор не предназначен для оценки реальной распространенности проблем или финансового эффекта.

## События

Событие содержит `event_id`, `ticket_id`, `product_id`, `text`, `source_channel`, `revision`, `event_type`, `batch_id`, `occurred_at`. Время задано фиксированным началом и смещением; текущее время не используется.

Повторная доставка сохраняет event ID и содержимое источника, но имеет другой пакет. Изменение получает новый event ID и следующую ревизию того же ticket ID. Sidecar-эталон имеет действие `insert`, `ignore_duplicate` или `update` и соответствует порядку доставки, включая одинаковые event ID у повторов.

Текущий API MVP еще не применяет версии событий. Эти файлы предназначены для следующей итерации надежности ingestion; исходные `inputs.json` можно импортировать уже сейчас. Поток не содержит эталонных категорий и команд для системы.

## Экспертная проверка

Сделайте две копии `expert-review.csv` вне каталога контрольного набора. Два эксперта независимо заполняют категорию, сценарий, группу эквивалентных проблем, наличие сигнала, имя и замечания. Для оценки повторяемости можно читать исходные `inputs`, не эталонные метки. Различия обсуждаются с третьим экспертом; решение и обоснование сохраняются отдельно, затем сравниваются с каталогом.

Группы экспертов сравниваются по парам обращений, а не по совпадению названий групп. Доля согласия, расхождения по категориям и решения арбитража должны сопровождать новую версию разметки. Слепой лист не содержит holdout и предложенных ответов; его состав обеспечивает присутствие всех шести категорий, но не представляет случайную выборку корпоративного потока.

На текущем этапе экспертная проверка не проведена: `expert_status=pending`. Для утвержденной разметки нужно обновить каталог и версию, заново сгенерировать набор и зафиксировать изменения. Не меняйте файлы контрольного набора вручную: проверка SHA-256 обнаружит расхождение.

## Команды

Из `cases/ai-agent/mvp`:

```bash
python -m dataset generate --size 500 --seed 20261105 --output /tmp/pulse-500
python -m dataset validate --directory /tmp/pulse-500
python -m unittest discover -s tests -p test_dataset.py -v
```

Размеры 1 000, 5 000 и 10 000 задаются тем же `--size`; минимальный поддерживаемый размер — 100. Новый путь обязателен: существующие данные и заполненные экспертные листы не перезаписываются. Совпадение версии, каталога, seed и размера должно давать побайтово одинаковые файлы.
