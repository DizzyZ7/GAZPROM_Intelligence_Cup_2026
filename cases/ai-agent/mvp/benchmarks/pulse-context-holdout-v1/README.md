# Контрольная оценка контекстного режима Pulse

Цель прогона — измерить, как правила P3 работают на новых формулировках и семействах проблем. Исходный режим `rules` и контекстный `context` получили одни и те же 152 обращения двух вымышленных продуктов. Эталон включает 36 групп и 84 положительные пары. Отдельные входы, разметка и описание состава доступны в [каталоге выборки](../../datasets/pulse-context-holdout-v1/README.md).

[Код и протокол зафиксированы в коммите](https://github.com/DizzyZ7/GAZPROM_Intelligence_Cup_2026/commit/6e406eac1fb347733707c7adbedd6181648c07fd) до открытия контрольных данных. SHA-256 манифеста набора — `03ac255190930bba59fb2c4d8bc8ed3e2326a736d847214583cbc5949f6fe932`. Сначала посчитаны предсказания обоих методов, затем прочитаны эталоны. Минимум для сигнала составлял два обращения. Подбор правил или порогов по этой выборке не проводился.

Контекстные правила чаще распознают категории, однако критерий ненулевой полноты группировки не выполнен. У 83 из 96 эталонных участников групп код отказа `insufficient_context`. Значение pairwise precision для метода без выданных пар установлено в 0 по соглашению расчета, а доля ложных объединений для него не определена. Время отражает один локальный запуск анализа в Python 3.12, без API, SQLite и эмбеддингов.

В выборке шесть обращений со встроенными инструкциями. Ни одно не вошло в сигнал. При этом ни одно не получило код `untrusted_instruction`, а у одного контекст был разрешен. Этот результат показывает пробел эвристики распознавания. Вызовы инструментов в этих режимах отсутствуют.

## Разбор ошибок

- Исходные правила объединили пожелание получать код восстановления на резервную почту с дефектом доставки кода на старую SIM-карту. Общий сценарий восстановления скрыл разные категории и причины. ID источников `t-361ea53150114bf49e848613e628d1cd` и `t-eb15d45ad6354dd8bac155e5cd035cf9`.
- Контекстный режим пропустил повтор одного дефекта CSV. В выгрузку попадали строки только с открытой страницы, причем формулировки описывали результат без явного слова «ошибка» или HTTP-кода. Обоим обращениям присвоен `insufficient_context`. ID источников `t-09a7b1e2509343ad8ea21b56cab4b974` и `t-444175f08c2442f3bb4b15d651413bf4`.
- Пожелания добавить отдел контактного лица выражены как необходимость отдельной графы и отсутствие поля для подразделения. Разбор отказался от обеих формулировок. ID источников `t-01ce86f2ca9d409d9a19131c09951e2c` и `t-afa2cca6d5f64f6d96b66951f1ecef23`.

Следующий критерий P3 — улучшить извлечение намерения и симптома на development и validation и проверить ненулевую полноту с контролем ложных объединений на новой независимой выборке. Текущий holdout сохраняется как исторический замер. Экспертная перепроверка разметки и качество на корпоративных обращениях остаются открытыми. Инференс реальной модели эмбеддингов в этой итерации не выполнялся.

## Проверка и воспроизведение

Из `cases/ai-agent/mvp` выполните проверку контрольных сумм артефактов, выборки и соответствия исходников зафиксированной конфигурации.

```bash
python -m context_eval verify \
  --dataset datasets/pulse-context-holdout-v1 \
  --output benchmarks/pulse-context-holdout-v1/holdout
```

Для независимого воспроизведения скопируйте зафиксированные параметры в новый рабочий каталог. Квитанция с отпечатком манифеста предотвращает повторную оценку в одном каталоге, включая повтор с другим именем файла параметров. Метрики классификации и группировки детерминированы. Время обработки зависит от среды.

```bash
pulse_run=$(mktemp -d)
cp benchmarks/pulse-context-holdout-v1/holdout/frozen-config.json "$pulse_run/"
python -m context_eval evaluate \
  --dataset datasets/pulse-context-holdout-v1 \
  --config "$pulse_run/frozen-config.json" \
  --output "$pulse_run/result"
```
