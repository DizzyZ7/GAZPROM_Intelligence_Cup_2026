# Проверка локального извлечения контекста

Офлайн-эксперимент сравнивает контекстные правила v2.3 с Qwen3.5:4b через локальный Ollama. Модель извлекает категорию, операцию и наблюдаемый симптом или запрошенное изменение. Для операции и симптома требуются дословные цитаты из обезличенного текста. Цель проверки — измерить покрытие новых сценариев и качество предложенных повторов.

## Контракт проверки

- Обращение поступает отдельным сообщением в роли пользователя. Провайдер отправляет только текст после NFKC и маскирования email и телефонов. Соединение идет по HTTP на `127.0.0.1:11434` с отключенными прокси и перенаправлениями. Инструменты модели недоступны.
- До вызова модели применяются защитные правила v2.3 и ограничение длины. Ответ проходит проверку схемы, буквального совпадения цитат с текстом, связи между фрагментами, отрицаний и наличия слов ключа в соответствующей цитате. Русские окончания допускаются по совпадению начала слова, числа и латинские коды сравниваются точно. Несогласованность приводит к воздержанию.
- Предложение о повторе формируется при точном совпадении проверенных категории, операции и симптома внутри одного продукта. Продукт берется из входных метаданных. Каждая группа требует проверки аналитиком.
- `evidence.json` содержит SHA-256 обезличенного текста, причину решения и полуоткрытые символьные границы цитат. Цитата восстанавливается срезом `sanitized_text(text)[start:end]`. Значения и статусы извлечения находятся в `structured/predictions.csv`.
- `frozen-config.json` связывает исходники, входные манифесты, хеш промпта, параметры и digest модели. На validation взята подвыборка из 24 обращений по фиксированному хеш-ранжированию ID. Финальный holdout включает 48 отдельных обращений. Эталонные метки читаются после двух серий предсказаний, а запуск holdout требует завершенного отчета validation.
- Категория, поиск пар и итоговая кластеризация оцениваются раздельно. Для цитат дополнительно считается число попаданий по каждому полю и по обоим сразу. Попадание требует символьного F1 не менее 0,5 хотя бы с одной эталонной цитатой. Эта метрика измеряет совпадение выделенных фрагментов. Смысл нормализованных формулировок и техническую причину оценивает аналитик.

Набор синтетический, а доменная проверка человеком ожидается. Выводы относятся к выбранной модели, настройкам и выборкам. Маскирование рассчитано на указанные форматы контактов. Шаблонные проверки недоверенных инструкций и связи цитат покрывают конечный набор конструкций.

## Результаты

| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| development (14) | Правила v2.3 | 8/14 | 0,300 | 7/14 | 0,000 | 0 / 0 / 0 | 0,000 |
| development (14) | Qwen с проверкой | 3/14 | 0,194 | 11/14 | 0,000 | 0 / 0 / 0 | 0,000 |
| validation (24) | Правила v2.3 | 17/24 | 0,699 | 8/24 | 0,400 | 1 / 0 / 3 | 0,400 |
| validation (24) | Qwen с проверкой | 13/24 | 0,558 | 13/24 | 0,000 | 0 / 0 / 4 | 0,000 |
| holdout (48) | Правила v2.3 | 9/48 | 0,110 | 38/48 | 0,000 | 0 / 0 / 18 | 0,000 |
| holdout (48) | Qwen с проверкой | 9/48 | 0,440 | 39/48 | 0,000 | 0 / 0 / 18 | 0,000 |

В подвыборке development отсутствуют эталонные пары. Поиск и кластеризация оцениваются по отдельным артефактам. В этом прогоне проверка на равенство ключей давала одинаковые наборы пар для обеих задач. При отсутствии предложенных пар доля ложных объединений в JSON равна `null`.

На holdout модель вызвана 47 раз. Обе эталонные цитаты совпали в одном из 42 случаев с разметкой фрагментов, в том числе в одном из 38 продуктовых обращений. Сервер принял контекст только этого обращения. Основные причины отказов — неподтвержденные цитаты (13), недопустимое содержимое полей (10) и слова ключа без опоры на цитату (9). В 16 из 18 пропущенных пар контекст хотя бы одной стороны оказался непригоден для сопоставления, у двух пар различались предсказанные категории.

Ни один из шести случаев с обязательным воздержанием не стал кандидатом. Две пробы с подложными инструкциями дошли до модели и получили ответ `unknown`. В пробах с контактами email замаскирован. Синтетический номер с префиксом `+0` остался в тексте локального вызова, поскольку текущий шаблон телефонов рассчитан на `+7` и `8`. Эти наблюдения относятся только к заданным пробам.

Holdout занял 551,3 с для Qwen с проверкой и 0,038 с для правил. Скорость Qwen составила 0,087 обращения в секунду с учетом защитных отказов и формирования пар. Ollama сообщил 3,08 ГБ загруженного состояния модели и 0 байт VRAM. Это последовательный CPU-прогон. Лимиты хоста и версия модели сохранены в [runtime.json](runtime.json).

Предварительный контрольный запуск остановлен до чтения эталонов после обнаружения двух обходов проверки цитат. Регрессии на отдельных синтетических примерах закрывают обрезанное отрицание и широкие цитаты с несвязанными операциями. Итоговый validation и holdout выполнены на повторно зафиксированном коде и одинаковых параметрах.

Модель остается офлайн-экспериментом. Для следующей проверки стоит отдельно измерить выделение цитат без генерации свободных ключей операции и симптома, затем проверить нормализацию этих фрагментов на новой контрольной выборке.

Развернутые матрицы, ошибки, замеры времени и доказательства доступны в каталогах методов. Таблицы сравнения — [development](development/comparison.csv), [validation](validation/comparison.csv), [holdout](holdout/comparison.csv).

## Воспроизведение

Команды выполняются из `cases/ai-agent/mvp`. Нужны Python 3.11 или 3.12, Ollama и локальная модель. Сохраненный прогон использовал Ollama 0.40.15 и Qwen3.5:4b Q4_K_M. Тег может измениться. Сверяйте digest, который печатает `freeze`, с сохраненным файлом конфигурации.

Запустите сервер с отключенным облаком.

```bash
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 OLLAMA_NUM_PARALLEL=1 ollama serve
```

В другой оболочке загрузите модель и выполните эксперимент в новом каталоге.

```bash
ollama pull qwen3.5:4b
pulse_reference=datasets/pulse-synthetic-v1
pulse_holdout=datasets/pulse-structured-holdout-v1
pulse_output=/tmp/pulse-structured-context-reproduction
python -m structured_eval freeze --reference "$pulse_reference" --holdout "$pulse_holdout" --output "$pulse_output"
python -m structured_eval evaluate --split validation --reference "$pulse_reference" --holdout "$pulse_holdout" --output "$pulse_output"
python -m structured_eval evaluate --split holdout --reference "$pulse_reference" --holdout "$pulse_holdout" --output "$pulse_output"
python -m structured_eval evaluate --split development --reference "$pulse_reference" --holdout "$pulse_holdout" --output "$pulse_output"
python -m structured_eval verify --reference "$pulse_reference" --holdout "$pulse_holdout" --output "$pulse_output"
```

Проверка сохраненных файлов выполняется без сервера.

```bash
python -m structured_eval verify \
  --reference datasets/pulse-synthetic-v1 \
  --holdout datasets/pulse-structured-holdout-v1 \
  --output benchmarks/pulse-structured-context-v1.1
```

Материалы контрольного набора описаны в [документации датасета](../../datasets/pulse-structured-holdout-v1/README.md). Контракт структурированного ответа приведен в [документации Ollama](https://docs.ollama.com/capabilities/structured-outputs).
