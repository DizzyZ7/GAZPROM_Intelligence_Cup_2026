Конфигурация: `16a5d8d5239b24af232d6a20a64a371a8382a39170a50d3d38dd4e62c20964eb`. Полные параметры, состояние TF-IDF, исходные SHA-256 и все варианты порогов находятся в `calibration/`; результаты и их манифест — в `holdout/`.

## Калибровка и интерпретация

На validation TF-IDF также не дал верных повторных пар на всей сетке. Среди 71 эталонной пары 61 была заблокирована отказом классификатора, 10 — несовпадающими предсказанными категориями; это проверено при минимальном пороге 0,05. Выбранное значение 0,95 определяется заранее заданным правилом равенства, а не доказанным качеством. В протоколе сохранено `calibration_status=no_true_positives`, лучший TP/F1 равны 0.

Во всех методах категории и сценарии задает общий действующий классификатор. На новых семействах текущие пять правил не обобщаются: они блокируют обращения до полезного сопоставления. Эти результаты не позволяют делать вывод о превосходстве или непригодности TF-IDF и семантических эмбеддингов как таковых. Следующее изменение должно устранять ограничение классификации и извлечения контекста; изменение одного порога его не решит.

Локальный Ollama и embedding-модель в среде эксперимента отсутствовали. Model C не выполнялась, ее числовые метрики оставлены пустыми. Тестовые векторы использовались только в автоматических тестах контрактов, в отчет не подставлялись. Итоговый статус эксперимента — `partial`.

## Время и ресурсы

Один локальный запуск Python 3.12.14 с tracemalloc: Rules — около 0,0461 с; TF-IDF — около 0,3844 с на 100 обращений. Пиковая traced Python memory — 1 873 864 и 7 158 042 байта соответственно. Состояние среды и точные значения сохранены в `holdout/manifest.json` и `*/performance.json`.

Это измерение работы офлайн-анализа с ограничением числа пар. Оно не включает запуск сервиса, очередь, запросы API, время обучения TF-IDF и не измеряет память внешнего процесса/GPU. Производительность корпоративного контура и нагрузочная устойчивость не проверялись.

## Проверка и использование

Из `cases/ai-agent/mvp`:

```bash
python -m benchmark verify --directory benchmarks/pulse-synthetic-v1/holdout
python -m unittest discover -s tests -p 'test_benchmark_*.py' -v
```

Финальная оценка выполнена после фиксации кода и конфигурации; `calibration/holdout-receipt.json` имеет статус `completed`. Повторный запуск в этом каталоге блокируется. Проверка артефактов не меняет параметры и не запускает модель повторно.

Опубликованный holdout нельзя использовать для настройки следующего алгоритма и затем выдавать его повторную оценку за независимую. Для следующего подтверждения качества необходим новый, отдельно зафиксированный набор ранее не использованных семейств либо согласованная корпоративная выборка. До этого результаты являются демонстрационной оценкой на синтетике, а не доказательством производственной готовности.
