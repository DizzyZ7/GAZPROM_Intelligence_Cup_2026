# Поиск кандидатов по подтвержденным цитатам

Поиск предлагает аналитику до трех обращений на один запрос. Каждое предложение содержит две оценки сходства и ссылку на проверяемые фрагменты. Решение о повторе остается за аналитиком.

## Эксперимент

- Сервер восстанавливает обе цитаты из обезличенного источника и проверяет признаки связи между ними. SHA-256 и символьные границы относятся к тексту после `quote_candidates.candidate_text`. Маскирование расширено для адресов с кириллическим доменом и местных телефонных форматов. Перечень распознаваемых форматов ограничен.
- До сравнения проверяются продукт, категория, совпадение распознанного кода с учетом регистра и отрицание в каждом фрагменте. Коды вне цитаты симптома, несколько разных кодов и обрезанная область отрицания приводят к отказу. Условие на отрицание консервативно и может исключить часть настоящих парафразов.
- BGE-M3 получает отдельно цитату операции и цитату симптома, в пакетах до 32 фрагментов через локальный `EmbeddingProvider`. Порог применяется к минимуму двух косинусных оценок. Эти оценки используются для ранжирования. Метод сравнения Snowball требует равенства обеих нормализованных цитат при тех же фильтрах.
- Порог выбирается только на validation. Сетка от 0,50 до 0,95 с шагом 0,05. Приоритеты выбора — максимальный F1 при наличии верных пар и precision от 0,80, затем precision и более высокий порог. При отсутствии подходящего порога семантические предложения отключаются. Конфигурация и набор зафиксированы до holdout.
- Validation и holdout используют отдельные синтетические цитаты, подготовленные как вход для поиска. В метрику повторов входят только `bug` и `feature_request`. Повторяющиеся вопросы и индивидуальные просьбы учитываются как непродуктовые обращения. Метки групп загружаются после вычисления сходства. Для holdout ранжирование также завершено до чтения меток. [Описание набора](../../datasets/pulse-quote-search-v1/README.md).
- В ретроспективе входом служат цитаты, прошедшие защитные проверки в PR №9. Артефакты проверяются по хешам опубликованного коммита. Применяются тот же порог и повторная проверка доказательств. Этот прогон показывает ограничения готовых результатов выделения цитат. [Зафиксированный PR №9](https://github.com/DizzyZ7/GAZPROM_Intelligence_Cup_2026/commit/f8ac4d9f8af48dbde8d62632bd358bc0a588fad4).
- Pairwise-метрики считают уникальные предложенные пары, top-3 считается по направлениям для каждого обращения. В `candidates.csv` все строки имеют статус `pending_human_review`. `evidence.json` содержит основания и причины отказа, `errors.json` — ложные предложения и пропуски. Квитанция предотвращает повторный запуск holdout в том же каталоге.

Выбран порог 0,700. Отчет указывает статус прогона и фактическое число фрагментов, отправленных в локальный провайдер.

При пустой выдаче доля ложных кандидатов имеет значение `null`. Замеры относятся к подготовке цитат, получению эмбеддингов и расчету пар на этих выборках. Ретроспектива использует уже сохраненные цитаты Qwen. [Параметры запуска](runtime.json).

На новом holdout 8 из 18 эталонных пар остановились из-за недопущенных цитат, еще 4 — из-за различий в признаках отрицания. Из 6 допустимых пар 1 прошла порог 0,70, у остальных оценки оказались ниже. BGE-M3 обработала 21 уникальный фрагмент с размерностью 1024. Время этапа поиска на CPU составило 1,28 с.

На сохраненных результатах Qwen до сравнения не дошла ни одна из 11 эталонных пар. В 9 парах не хватило принятых цитат, в 2 различались признаки отрицания.

На validation запись об устраненном сбое с формулировкой «сбой исправили» прошла проверку цитат при обязательном воздержании. Ее не было среди предложений. На holdout соблюдены все 8 обязательных воздержаний. Этот результат показывает ограничение проверки статуса устранения.

Эксперимент остается офлайн. Синтетическая разметка требует независимой доменной проверки.

Подробные метрики и списки кандидатов доступны для [validation](validation/report.json), [holdout](holdout/report.json) и [ретроспективы](retrospective/report.json).

## Воспроизведение

Команды выполняются из `cases/ai-agent/mvp` на Python 3.11 или 3.12. Установите зависимости разработки и запустите локальный Ollama.

```bash
python -m pip install -r requirements-dev.txt
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 OLLAMA_NUM_PARALLEL=1 ollama serve
```

В другой оболочке загрузите BGE-M3 и запустите эксперимент в новом каталоге. Версию Ollama и digest модели сверяйте с `frozen-config.json`.

```bash
ollama pull bge-m3:567m
pulse_data=datasets/pulse-quote-search-v1
pulse_output=/tmp/pulse-quote-search
python -m quote_candidates_eval calibrate --dataset "$pulse_data" --output "$pulse_output"
python -m quote_candidates_eval holdout --dataset "$pulse_data" --output "$pulse_output"
python -m quote_candidates_eval retrospective --dataset "$pulse_data" --output "$pulse_output"
python -m quote_candidates_eval verify --dataset "$pulse_data" --output "$pulse_output"
```

Сохраненный отчет проверяется без запуска модели.

```bash
python -m quote_candidates_eval verify \
  --dataset datasets/pulse-quote-search-v1 \
  --output benchmarks/pulse-quote-candidates-v1
```
