# Независимый инженерный синтетический контроль Pulse

Версия: `pulse-independent-20261109`. Фиксированный seed: `20261109`.
Никакие текущие дата, время, сетевые сервисы или модели при генерации не нужны.

Состав: development — 300, validation — 100, новый holdout — 120 обращений.
Два продукта вымышлены. В holdout 80 обращений образуют 20 продуктово
изолированных групп по четыре варианта, еще 40 намеренно не получают группу.
Категории holdout: bug — 52; feature_request — 34; how_to — 8;
service_request — 8; other — 8; unknown — 10.

`development.inputs.json`, `development.labels.jsonl`, `validation.inputs.json`
и `validation.labels.jsonl` скопированы побайтно из `pulse-synthetic-v1`
локальной ревизии `a390b3df78944b2a0a89dd5dba1748c0fb6f5a30`. Все четыре файла
дополнительно побайтно сверены с git-объектами актуального main
`3f024406e892f6649cbc8469302d60b6205b2922` и с разрешенными файлами рабочего
checkout: содержимое полностью совпадает. Эти
четыре файла не являются новой независимой разметкой. Не переоценивайте их
как новый тест: они сохраняют назначение для разработки и настройки.

Каждый файл `.inputs.json` содержит только `id`, `product`, `text`, `channel`.
Новый holdout использует непрозрачные 64-символьные SHA-256 идентификаторы.
Эталон находится в отдельном `.labels.jsonl`, связан с входом по ticket_id
и перемешан независимо от входов. Каталог содержит тексты и gold: не
передавайте его анализатору и не считайте его входными признаками.

В новых группах объединено одно явно наблюдаемое нарушение одной операции
либо одно конкретное пожелание одного продукта. Сходство симптомов в разных
операциях не доказывает общую проблему. Никакие HTTP-коды, скрытые причины,
инфраструктурные объяснения или факты, которых нет в обращении, в gold не
додумываются. Похожие тексты разных продуктов не связываются. Две равнозначные
независимые задачи, недостаточный контекст и сообщение только с атакующими
инструкциями получают unknown и остаются без кластера. Редкие однократные
дефекты и пожелания сохраняют категорию, но повторяющимся сигналом не считаются.

Команды внутри недоверенного обращения не управляют обработчиком. Если в
таком сообщении есть конкретный продуктовый факт, он сохраняет обычную
категорию и связь с проблемой. Имеются отрицания, пересечение словаря между
разными операциями, буквальные совпадения текста между продуктами, смешанные
запросы и полностью синтетические контакты. Адреса используют example.invalid;
телефон является недействующим макетом с кодом +0. Реальных персональных
данных и производственных обращений здесь нет.

Независимость обеспечена отдельным авторством: при подготовке нового
holdout не читались текущая реализация классификации/кластеризации,
benchmark-код, новые unit-тесты, предсказания или результаты экспериментов.
Разрешенные продуктовые документы задавали задачу; старый dataset/catalog.py
и прежний pulse-context-holdout-v1 использовались для исключения уже занятых
смысловых проблем и потребностей. Группы и формулировки написаны вручную,
без генерации вариантов моделью во время исполнения скрипта. Код/правила
анализатора не использовались как подсказки для выбора слов или gold.

Это независимая инженерная синтетика, а не подтвержденный корпоративными
данными или доменным экспертом набор. Разметку составил один AI-автор; второй
эксперт, арбитраж и оценка согласия отсутствуют. expert_status во всех новых
эталонах — pending_human. Частоты намеренно подобраны для покрытия, а не для
оценки распространенности проблем. Варианты не являются независимыми
сообщениями реальных клиентов. Проверка схемы и SHA не доказывает корректность
семантического эталона. Человеческая предметная проверка обязательна для
экспертного заключения и этой работой не заменяется.

До фиксации алгоритма и его предсказаний не открывайте новые holdout-входы,
labels, catalog или разделы генератора с текстами. После настройки по этому
набору для итоговой оценки потребуется другой независимый контроль.
Разделение файлов организационное, а не криптографическое ограничение доступа.

Воспроизведение (Python 3.10+, только stdlib):

```sh
python /tmp/pulse-independent-20261109/generate_dataset.py --output /tmp/pulse-independent-20261109/benchmark --verify-reproducible
python /tmp/pulse-independent-20261109/generate_dataset.py --check /tmp/pulse-independent-20261109/benchmark
```

Генератор читает закрепленные побайтные source_snapshots рядом со скриптом,
проверяет их SHA/размеры, восстанавливает каталог, все шесть файлов набора,
manifest и этот README. Для переноса сохраните скрипт вместе с source_snapshots.
`--verify-reproducible` повторяет генерацию в отдельном временном каталоге и
сравнивает все девять генерируемых файлов байт в байт. Структурная проверка
выполняется всегда; `--check` проверяет уже созданный каталог без изменения.
Проверяются точный состав признаков, связь sidecar, категории, размеры групп,
разделение продуктов, отсутствие групп у unknown/составных/однократных случаев,
контрольные суммы и точное сохранение development/validation.
