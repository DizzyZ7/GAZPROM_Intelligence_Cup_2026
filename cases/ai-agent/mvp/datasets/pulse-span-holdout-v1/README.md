# Слепая выборка TIIm Pulse

Версия `pulse-span-holdout-v1`. В `holdout.inputs.json` лежат входные обращения, в `holdout.labels.jsonl` — эталонная разметка по `ticket_id`. Разметка предназначена для проверки после фиксации варианта системы. `manifest.json` содержит число обращений, размеры и SHA-256 файлов.

## Правила разметки

- Один кластер объединяет сообщения об одной текущей проблеме или одной запрашиваемой возможности в рамках продукта и категории. Для сбоев совпадают операция и существенное проявление. Код ошибки учитывается, когда он различает проявления. Кластеры обозначают совпадение пользовательских сообщений. Причина сбоя по ним может быть неизвестна.
- `issue_id` идентифицирует размеченный случай. Совпадение `issue_id` у нескольких обращений означает повтор. `gold_cluster_id: null` отмечает одиночный сигнал или воздержание от группировки. `expected_signal` истинно для одного выделяемого текущего сбоя или запроса на изменение продукта.
- `operation_evidence` и `symptom_evidence` содержат дословные фрагменты исходного текста. Для запроса функции второй список указывает на ограничение текущего процесса. Варианты в одном списке описывают один аспект. Контакты лежат за пределами эталонных фрагментов.
- `must_abstain` применяется к обращениям без выделяемого сигнала для группировки. Оба списка цитат тогда пусты, а `reason` объясняет решение. Две независимые текущие проблемы требуют воздержания. Если рядом описан явно устранённый сбой, для единственной текущей проблемы размечаются её собственные фрагменты. Формулировка с «не» может сообщать о наблюдаемом сбое или явно отрицать его наличие.

## Состав

| Проверка | Количество |
| --- | ---: |
| Обращения / вымышленные продукты / каналы | 36 / 5 / 5 |
| Обращения в кластерах / кластеры / пары повторов | 16 / 7 / 11 |
| Кластеры по два / по три обращения | 5 / 2 |
| Одиночные сигналы / обращения с воздержанием | 10 / 10 |
| Близкие одиночные сигналы с той же операцией и другим проявлением | 4, включая 1 с другим кодом |
| Близкие одиночные сигналы с тем же проявлением и другой операцией | 2 |
| Пары с одинаковым текстом в разных продуктах | 1 |
| Вопросы вне продукта | 2 |
| Отдельные гипотетические / устранённые / явно отрицаемые сбои | 1 / 1 / 1 |
| Текущая проблема рядом с историей / две текущие проблемы | 1 / 1 |
| Попытки подменить инструкции / тестовый телефон / тестовая почта | 2 / 1 / 1 |

Строки таблицы описывают пересекающиеся проверки. Все тексты написаны для этого набора, продукты вымышлены, контакты тестовые. Доли случаев заданы вручную. Такая выборка подходит для проверки отдельных сценариев, а для оценки качества на реальных обращениях нужны данные с естественным распределением тем и формулировок.
