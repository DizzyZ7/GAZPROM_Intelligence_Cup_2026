# Независимая оценка методов ТИИм Pulse

Пакет сравнивает три способа обнаружения повторов на версионированных обращениях. Оценка не изменяет рабочую SQLite и не публикует сигналы. Стандартной библиотеки Python достаточно; внешние ML-сервисы не вызываются.

Сохраненный эксперимент: [результаты и ограничения](../benchmarks/pulse-synthetic-v1/README.md). Rules/TF-IDF выполнены, модель Embeddings не проверена; нынешние результаты показывают ограничение общего классификатора.

## Что именно сравнивается

| Метод | Представление и сопоставление | Классификация |
| --- | --- | --- |
| Rules | Граница продукта, категории и сценария; одинаковый контекст образует группу | Текущие правила `pulse.classify` |
| TF-IDF | Word 1–2 и char 3–5 n-grams, cosine, тот же контекст и калиброванный порог, complete-link | Тот же классификатор |
| Embeddings | Явный локальный `EmbeddingProvider`, cosine, тот же контекст и калиброванный порог, complete-link | Тот же классификатор |

Это контролируемое сравнение поиска повторов и группировки с общим классификатором. Качество трех разных классификаторов не заявляется. Матрица ошибок категории одинакова у выполненных вариантов; показатель сохраняется отдельно, чтобы ограничение правил не скрывалось в метриках сходства. Категория, сценарий и отказ вычисляются из текста; эталонные значения не используются для границ кандидатов.

Complete-link допускает обращение в кластер, только если оно сопоставлено со всеми его участниками. Поэтому похожие пары A–B и B–C при различающихся A–C не образуют общий кластер. Кластеры из одного источника не образуют кандидат в сигнал. Семантическое сходство и эталонный `issue_id` не доказывают общую техническую первопричину.

## TF-IDF

Словарь и document frequency вычисляются только на development. Для частоты `tf > 0` используется `1 + ln(tf)`, для document frequency `df` — `idf = 1 + ln((1 + N) / (1 + df))`. Каждая из ветвей word/char нормируется по L2, затем объединенные векторы снова нормируются. При наличии обеих ветвей каждая получает половину квадрата нормы.

Word n-grams имеют длину 1 и 2. Character n-grams длиной 3, 4 и 5 строятся внутри каждого слова с пробелами по краям. Неизвестные термы при transform не добавляются в словарь и не меняют IDF. Пустые векторы TF-IDF имеют нулевое сходство; нулевые или некорректные embedding-векторы считаются ошибкой провайдера.

До классификации и вычисления представления применяется существующее маскирование телефона РФ и email. Оно не заменяет полный privacy gateway. В функции анализа передаются только `Ticket(id, product, text, channel)`.

## Отдельные задачи и знаменатели

| Задача | Показатели | Что считается ошибкой |
| --- | --- | --- |
| Категория | Accuracy, macro Precision/Recall/F1, показатели шести классов, confusion matrix, доля `unknown` | Неверная категория; отказ учитывается как предсказание `unknown` |
| Похожие пары | Precision/Recall/F1 до итоговой группировки | Принята разная проблема или пропущена эталонная повторная пара |
| Top-5 | Precision@5, точность возвращенных соседей, Recall@5, доля найденных запросов с повторами | Нерелевантные соседи, отсутствие выдачи и неполная выдача |
| Кластеры | Pairwise Precision/Recall/F1 после complete-link, ложные объединения, пропущенные повторы, число кандидатов/одиночных обращений | Совместное включение в разные эталонные проблемы или разрыв повторяющейся проблемы |

Pairwise метрики учитывают все `N × (N − 1) / 2` пары, включая обращения, на которых классификатор отказался от решения. Положительный эталон — одинаковый непустой `gold_cluster_id`. Вопросы, неизвестное и многопроблемный текст не получают общий кластер; их автоматическое объединение штрафуется.

`false_merge_fraction = FP / (TP + FP)`, `missed_repeat_fraction = FN / (TP + FN)`. Если знаменатель отсутствует, значение — `null`. Для Precision/Recall/F1 нулевой знаменатель дает 0 по фиксированному соглашению. Macro усредняется по шести заданным классам, включая отсутствующие; support каждого класса показан рядом.

Top-5 строится после контекстных ограничений и порога. Precision@5 делит число верных направленных соседей на `5 × число запросов`; отдельная точность возвращенных соседей делит его на фактическое число результатов. Recall@5 делит число найденных верных соседей на все эталонные направленные связи. Пустая выдача не исключается из оценки полноты.

## Воспроизводимый протокол

1. `tune` читает development-признаки и validation-признаки/эталоны. Holdout-файлы не открываются. Хеш манифеста, включающего их контрольные суммы, допустим как идентификатор набора.
2. Состояние TF-IDF сохраняется в JSON, без pickle. Сетка порогов заранее фиксирована: 0,05–0,95 с шагом 0,05. Скоринг выполняется один раз, далее переиспользуются вычисленные значения.
3. Порог выбирается по pairwise F1 итоговых кластеров на validation. Равенство сравнивается по точным дробям счетчиков, затем выбирается меньшее число FP и больший порог. Сетка и все кандидаты сохраняются в `validation-grid.csv`. Если верных пар нет, фиксируются `calibration_status=no_true_positives`, лучший F1/TP и число эталонных положительных пар; выбранное по правилу равенства значение не считается подтвержденным полезным порогом. Отсутствие положительных эталонов отдельно отмечается как `no_positive_gold`.
4. `frozen-config.json` содержит параметры, состояние методов, SHA-256 набора, TF-IDF и исходных файлов. Его собственная контрольная сумма выявляет случайное изменение настроек; это не цифровая подпись и не защита от владельца файлов.
5. `evaluate` проверяет протокол, состояние и исходный код; новых параметров порога не принимает. Для модели нужен тот же descriptor версии. После этого создается квитанция `holdout-receipt.json`, запрещающая повторный финальный запуск из того же каталога калибровки.
6. `verify` проверяет полноту и контрольные суммы сохраненного отчета без повторного инференса. Исторический отчет остается проверяемым после изменения кода; поле `source_matches_current` показывает соответствие текущей реализации.

Квитанция защищает от случайного повторного использования, а не от сознательного копирования каталогов. После неуспешной финальной оценки она остается со статусом `failed`; новый эксперимент требует отдельного зафиксированного протокола и решения о допустимости использования тестовых данных. По опубликованному holdout нельзя подбирать следующий вариант алгоритма и затем представлять его оценку на том же наборе как независимую.

## Команды

Из `cases/ai-agent/mvp`; выходные каталоги должны быть новыми:

```bash
python -m benchmark tune --dataset datasets/pulse-synthetic-v1 --output /tmp/pulse-calibration
python -m benchmark evaluate --dataset datasets/pulse-synthetic-v1 --calibration /tmp/pulse-calibration --output /tmp/pulse-holdout
python -m benchmark verify --directory /tmp/pulse-holdout
python -m unittest discover -s tests -p 'test_benchmark_*.py' -v
```

Для установленной локальной модели добавьте одинаковый `--ollama-model ИМЯ_МОДЕЛИ` к `tune` и `evaluate`. Имя и digest считываются из локального Ollama `/api/tags`; транспорт запрещает перенаправления и proxy. Модель автоматически не скачивается. Пример адаптера для программного запуска:

```python
from benchmark.protocol import calibrate, evaluate

# provider реализует semantic.EmbeddingProvider в согласованном контуре.
descriptor = {
    "provider": "internal",
    "model": "approved-model",
    "revision": "immutable-version",
}
calibrate(dataset_path, calibration_path, provider=provider, descriptor=descriptor)
evaluate(
    dataset_path,
    calibration_path,
    output_path,
    provider=provider,
    descriptor=descriptor,
)
```

Этот контракт не утверждает наличие корпоративной интеграции или совместимость ее HTTP API с Ollama. Ответственность за достоверность descriptor внутреннего адаптера лежит на его реализации.

Если провайдер не задан, Embeddings имеет статус `not_checked` («не проверено») с пустыми метриками. Некорректный ответ или ошибка во время запуска имеет статус `failed` с типом ошибки без исходного текста обращения. Технические тестовые векторы не подставляются вместо модели в реальном эксперименте. Если модель была откалибрована, ее отсутствие или смена версии блокирует финальный запуск до чтения holdout.

## Артефакты

Для каждого выполненного метода сохраняются `report.json`, `performance.json`, `predictions.csv`, `confusion.csv`, `retrieval.csv`, `groups.json`, `errors.json`. Ошибки разделены на классификацию, ложные совпадения и пропуски поиска/кластеризации; примеры содержат исходные ID, обезличенные фрагменты, фактическую причину отказа и score. Объяснения моделью не генерируются.

В корне отчета — `comparison.csv`, `comparison.md`, копия зафиксированного протокола и манифест SHA-256. Для непроверенной модели сохраняются только статус и пустой performance, числовые значения не выдумываются. Итоговый статус `partial` означает, что хотя бы один метод не выполнен успешно.

Измеряются время классификации, представления, парного скоринга, кластеризации, общее и CPU-время, обращения/сек и пиковая traced Python memory. Fit TF-IDF измеряется отдельно. Время провайдера входит в wall time, но память и CPU процесса Ollama/GPU не измеряются. Tracemalloc создает накладные расходы. Это один локальный эксперимент, не нагрузочное испытание промышленного сервиса.

По умолчанию ограничение — 200 000 пар на оцениваемую выборку. Большие корпуса требуют индекса кандидатов и отдельного нагрузочного протокола; генератор данных поддерживает большие размеры независимо от этого ограничения. Пропорции и семейства синтетического набора не воспроизводят реальную распространенность обращений. Экспертная проверка разметки пока ожидается.
