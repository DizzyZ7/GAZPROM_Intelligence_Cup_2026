# Независимая проверка части разметки

Пакет содержит 40 обезличенных синтетических обращений из development и validation. Выборка случайная, seed `20261109`; предложенных ответов и holdout в ней нет. Получены комментарии Димы к пяти строкам. Полный заполненный CSV ожидается, статус пакета — `pending`.
Комментарии сохранены с исходными формулировками, ID обращений и хешем пакета. Предложения по названиям сценариев и вопрос к детализации эталона №2 записаны отдельно. [Частичная обратная связь](partial-dmitry-feedback.json).


Сохраните копию `review.csv`. Заполняйте только четыре колонки `reviewer_*`; исходные ID, продукт, текст и канал не изменяйте. Каждый рецензент работает со своей копией без доступа к эталонным меткам и ответам другого рецензента.

Категории:

| Значение | Смысл |
| --- | --- |
| `bug` | Наблюдаемая проблема продукта |
| `feature_request` | Запрос новой возможности |
| `how_to` | Вопрос о порядке действий |
| `service_request` | Индивидуальное действие поддержки, например выдача доступа |
| `other` | Нет продуктовой проблемы или потребности |
| `unknown` | Не хватает фактов или нельзя выделить одну задачу |

В `reviewer_workflow` укажите сценарий, например `booking_queue`, `report_export`, `account_access`, `attachments`, `payment`, `contact_edit` или `unclassified`. Если ни один имеющийся сценарий не подходит, предложите название и поясните его в комментарии.

В `reviewer_cluster_id` укажите собственный условный ID только для нескольких обращений об одной наблюдаемой проблеме или потребности. Группы рассматриваются отдельно в каждом продукте. Совпадения слов или общего HTTP-кода недостаточно: сравните операцию и наблюдаемый результат. Не предполагайте техническую причину или код ошибки, которых нет в источнике. Одиночные и непродуктовые обращения оставьте без группы. Группы сравниваются по парам, а не по написанию ID.

В `reviewer_comment` фиксируйте неоднозначность, неполноту доказательства или сомнение в предложенной категории. Формулировка «файл не найден» сама по себе не доказывает наличие HTTP 404; сообщение о проблеме со вложением может означать отсутствие самого доказательства, а не сбой продукта.

Проверка заполненной копии из `cases/ai-agent/mvp`:

```bash
python -m dataset.review check \
  --dataset datasets/pulse-synthetic-v1 \
  --packet reviews/pulse-synthetic-v1-20261109 \
  --completed /tmp/reviewer-1.csv \
  --reviewer reviewer-1 \
  --output /tmp/reviewer-1-assessment.json
```

Команда проверяет состав и сохранность источников, полноту аннотаций, отдельно считает согласие категорий, сценариев и пар. Она сохраняет расхождения, но не изменяет эталоны. Статус `submitted` означает получение заполненного файла, а не подтверждение истинности разметки или личности рецензента. Разногласия двух рецензентов требуют отдельного арбитража и версии датасета.

Согласие на 40 примерах не подтверждает качество на всем наборе или корпоративном потоке. В подмножестве может отсутствовать часть повторов; pairwise-метрика описывает только рассмотренные пары. Для промышленной оценки потребуется согласованная обезличенная выборка реальных обращений.

Новый пакет создается без чтения gold и holdout:

```bash
python -m dataset.review prepare --dataset datasets/pulse-synthetic-v1 \
  --output /tmp/pulse-review-new --count 40 --seed 20261109
```

Существующий каталог или отчет не перезаписываются. Передача файла рецензенту и фактическая доменная проверка выполняются командой проекта.
